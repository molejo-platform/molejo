# Cluster Agent Operations

The Cluster Agent is a pre-alpha outbound connector. It does not reconcile
workloads yet. The Operator can be installed first; the Agent then starts as
`Unpaired`, remains ready, and waits for configuration without opening an inbound
management port.

## Installation identity

`molejoctl control-plane install` creates `molejo-agent-ca` with `ca.crt` and
`ca.key`, plus `molejo-agent-server-tls` with `tls.crt` and `tls.key`, in
`molejo-control-plane`. The server certificate covers
`control-plane-api.molejo-control-plane.svc.cluster.local`. Keep the CA key outside
Git and mount it only on the API pod.

The Agent ServiceAccount can only get, update, and patch
`molejo-agent-identity` and `molejo-agent-enrollment` in `molejo-system`. It cannot
list Secrets or access Molejo CRDs. The private key is generated by the Agent and
never leaves `molejo-agent-identity`.

## k3s installation

Install the Operator and Agent with `molejoctl cluster install`, then run
`molejoctl control-plane install`. The second command creates or reuses the
ECDSA P-256 CA, internal server certificate, database credentials, and initial
enrollment invitation. It installs PostgreSQL and the API, configures the Agent
with the internal HTTPS and gRPC endpoints, and waits until the Agent is
`Paired`. Credentials are stored in Kubernetes Secrets and are only printed
when `--show-generated-credentials` is explicitly used.

## Pairing

The initial in-cluster Agent is paired automatically by the control-plane
installer. For additional Agents, an installation administrator calls `POST
/api/v1/admin/agent-installations` and transfers the returned single-use token
to `molejo-agent-enrollment` without placing it in Git, shell history, logs, or
chat.

The Agent persists its key, CSR, and attempt ID before enrollment, so a timeout
or crash retries the same operation. A successful response is validated against
the local key, Agent CA, certificate expiry, and installation URI before being
persisted. The token is then removed and the Agent opens the TLS 1.3 mTLS stream.

`/healthz` reports process health. `/readyz` remains successful in
`Unconfigured`, `Unpaired`, `Enrolling`, `Connecting`, and `Paired`; it becomes
unavailable while the process is `Initializing`, `Stopping`, or `Failed`.
`/status` exposes the current state without identity material. `Failed` means the
local identity Secret is unreadable, unwritable, partial, invalid, or expired.

The Agent bounds each control-plane response wait to ten seconds. A missing hello
or heartbeat acknowledgement closes the stream and returns to the existing
connection backoff. During termination, the Agent marks readiness unavailable,
cancels the runner, shuts down the health server, and waits up to twenty seconds;
the Pod termination grace period is thirty seconds.

This increment has no automatic certificate rotation. A seven-day certificate
must not be treated as a production lifecycle; re-pairing is the temporary
pre-alpha recovery path.
